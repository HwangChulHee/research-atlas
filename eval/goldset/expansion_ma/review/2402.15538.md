## 초록+서론 한글 번역
LLM의 성공으로 LLM 에이전트 개발이 급속히 진전됐다. 에이전트의 토대는 생성 모델이지만 최적의 추론 전략과 에이전트 아키텍처 설계가 결정적이다. 이에 따라 LLM 에이전트 연구는 단순 chain-of-thought 프롬프팅에서 더 복잡한 ReAct·Reflection 추론 전략으로, 에이전트 아키텍처도 단일 에이전트 생성에서 멀티에이전트 대화, 나아가 multi-LLM 멀티에이전트 그룹챗으로 진화했다. 그러나 기존의 복잡한 프레임워크·라이브러리로는 새 추론 전략·아키텍처를 만들고 평가하기가 복잡한 도전이 되어 LLM 에이전트 연구 탐구를 저해한다. 이에 새 AI 에이전트 라이브러리 AgentLite를 오픈소스로 공개한다. AgentLite는 경량·사용자 친화 플랫폼으로 과제 지향 프레임워크이며, 에이전트의 과제 분해 능력을 높이고 멀티에이전트 시스템 개발을 촉진한다.

서론: LLM 에이전트는 LLM에 도구 사용과 환경 상호작용 능력을 더해 실시간 피드백으로 상호작용 루프를 닫고, 일회성 생성에서 다단계 행동 실행으로 과제 해결 능력을 확장한다(BabyAGI, AutoGPT 등). 추론 전략으로 ReAct는 실행 정확성을 높이고, Reflection은 성능을 향상시키며, ReWOO는 추론과 관찰을 분리하고, Divergent Think도 효과적 전략으로 검증됐다. 아키텍처 면에서 LangChain은 도구 에이전트 개발을 단순화하고, BOLAA는 여러 아키텍처를 비교하며 멀티에이전트 프레임워크를 제안하고, AutoGen은 새 멀티에이전트 대화 메커니즘과 코드 실행을 개발했으며, α-UMi는 multi-LLM 에이전트를 도입해 작은 LLM 여러 개를 파인튜닝해 GPT-4를 능가하기도 한다.

새 추론 타입·아키텍처의 구현·검증을 가속할 경량 라이브러리가 필요하다. 기존 라이브러리는 진전을 이뤘으나 에이전트의 근본 설계를 겨냥하지 않는다. 예로 LangChain은 새 추론 타입·아키텍처 구현에 지나치게 복잡하고 리팩터링 오버헤드가 크며, AutoGen은 추론 타입이 하드코딩되고 아키텍처가 멀티에이전트 대화+코드 실행으로 고정돼 새 연구 시나리오에 부적합할 수 있다. 이에 AgentLite를 도입한다. 핵심 특징: 경량 코드 아키텍처, 과제 지향 설계 원칙, 매니저 에이전트를 통한 계층적 멀티에이전트 오케스트레이션, 벤치마킹·실배포를 위한 다목적 구현 잠재력. Table 1에서 AutoGen·LangChain·Camel·CrewAI와 비교하며 AgentLite는 1k 미만 코드로 포괄적 능력을 달성한다.
