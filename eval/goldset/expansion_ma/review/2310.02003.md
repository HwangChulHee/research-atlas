## 초록+서론 한글 번역
트랜스포머 기반 LLM은 고정된 컨텍스트 윈도우에 제약되어 길고 일관된 출력을 생성하기 어렵다. 메모리 증강 LLM이 유망한 해법이지만, 기존 접근은 (1) 메모리 읽기에만 집중해 그 진화를 새 메모리의 단순 이어붙임으로 축소하거나 (2) 다른 도메인에 적응 못하는 매우 특화된 메모리를 써서 긴 출력 생성 과제를 다루지 못한다. 본 논문은 최초의 실용적 LLM 기반 범용 저장프로그램 자동 컴퓨터(폰노이만 아키텍처) 프레임워크인 L2MAC을 제시한다. 이는 LLM 기반 멀티에이전트 시스템으로, 길고 일관된 출력 생성을 위한 것이다. 메모리는 두 요소로 구성된다: 과제 해결용 프롬프트 프로그램이 채워지는 명령 레지스트리와, 최종·중간 출력을 담는 파일 저장소. 각 명령은 별도 LLM 에이전트가 실행하며, 그 컨텍스트는 정밀한 메모리 읽기/쓰기가 가능한 컨트롤 유닛이 관리한다. L2MAC은 시스템 설계 과제의 대규모 코드베이스 생성에서 SOTA를 달성하고, 책 한 권 쓰기 같은 범용 장문 텍스트 과제에도 작동한다.

서론: GPT-3/InstructGPT/GPT-4 등 LLM은 고품질 텍스트 생성에 성공했지만 고정 크기 c의 컨텍스트 윈도우에 제약된다. 이는 대규모 코드베이스처럼 방대하고 논리적으로 일관된 출력 구조 생성에서 치명적이다. LLM은 짧은 코드 스니펫은 잘 만들지만, 유한 컨텍스트 윈도우로 인한 정보 손실·문맥 절단 때문에 광범위하고 내부적으로 일관된 코드베이스는 생성하기 어렵다. 자연스러운 해법은 외부 메모리 저장소로 확장하는 것이나, 기존 방법은 외부 코퍼스로 암묵 지식 확장, 긴 대화·요약, 변수 값 유지 등에 그치고 다른 과제에 적응 못하거나 단순 append 전략으로 오류가 사실상 되돌릴 수 없으며 일관성 유지 메커니즘이 없다. 효과적 대규모 코드 생성은 세 핵심 속성을 요구한다: (P1) 과제지향 컨텍스트 관리, (P2) 전체 메모리에 대한 정밀 읽기/쓰기 도구, (P3) 생성 출력 검사. 저자들은 L2MAC(및 코드 생성용 인스턴스 Code-L2MAC)을 도입한다. Control Unit(CU)이 개별 LLM 에이전트들의 실행과 메모리 상호작용을 오케스트레이션한다. 먼저 LLM 에이전트가 상세 과제로부터 명령 목록 I를 생성하고, CU가 각 명령마다 다음 미해결 명령과 과거 실행 정보를 담도록 컨텍스트를 재단(P1)하며, 메모리 읽기/쓰기·확장 능력을 부여(P2)하고, 문법 오류·자가 생성 단위테스트로 출력을 검사(P3)해 교정한다. HumanEval에서 90.2% Pass@1을 달성한다.
